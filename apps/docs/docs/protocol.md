# Generative UI Protocol (GUIP)

The **Generative UI Protocol (GUIP)** defines a standardized, compact, and extensible format for representing user interfaces generated by AI models and rendered natively by frontend view frameworks.

The key design vision is:
1. **AI systems generate interfaces.**
2. **Frontend frameworks render interfaces.**
3. **AI never generates frontend code.**
4. **AI only generates protocol-compliant UI AST.**

---

## Universal AST Node Structure

The primary payload of the protocol is the **UINode** representation.

```typescript
type UINode = {
  id?: string;               // Optional stable identifier for reconciliation
  t: string;                 // Component Type (e.g. "button", "chart", "page")
  p?: Record<string, any>;   // Component Properties/Attributes
  c?: UINode[];              // Child nodes (content projection)
}
```

### Low Token Usage
To minimize prompt context and API output tokens, GUIP uses highly condensed key names:
- `t`: Type
- `p`: Props
- `c`: Children

---

## AST Document Wrapper

Every interface payload is enclosed in a standard document wrapper that contains version metadata:

```json
{
  "version": "1.0.0",
  "root": {
    "t": "page",
    "p": {
      "title": "Analytics dashboard"
    },
    "c": [
      {
        "t": "kpi",
        "p": {
          "label": "Daily Visitors",
          "value": "12,450"
        }
      }
    ]
  }
}
```

## Core Components Catalog

GUIP specifies 23+ core primitives divided into categories:

| Component Type | Category | Props Description | Events Dispatched |
| :--- | :--- | :--- | :--- |
| `page` | Layout | `title`, `subtitle` | - |
| `section` | Layout | `title`, `description`, `border` | - |
| `grid` | Layout | `cols` (1-12), `gap` (0-8) | - |
| `flex` | Layout | `direction` (row/col), `align`, `justify` | - |
| `stack` | Layout | `direction` (horizontal/vertical), `gap` | - |
| `card` | General | `title`, `subtitle`, `bordered` | - |
| `text` | General | `content`, `size`, `color`, `bold` | - |
| `heading` | General | `text`, `level` (1-6) | - |
| `button` | General | `label`, `variant`, `size`, `disabled` | `click` |
| `input` | Forms | `label`, `placeholder`, `value`, `type` | `input`, `change` |
| `textarea` | Forms | `label`, `placeholder`, `value`, `rows` | `change` |
| `select` | Forms | `label`, `options` (label/value), `value` | `change` |
| `checkbox` | Forms | `label`, `checked`, `disabled` | `change` |
| `table` | Data | `columns` (header/accessor), `data` | - |
| `chart` | Data | `type` (line/bar/pie), `data`, `height` | - |
| `kpi` | Data | `label`, `value`, `subtext`, `trend`, `trendValue` | - |
| `timeline` | Data | `items` (title, date, description, status) | - |
| `tabs` | General | `items` (label/value), `activeTab` | `tabChange` |
| `dialog` | Overlay | `title`, `description`, `open` | `close` |
| `drawer` | Overlay | `title`, `position` (left/right), `open` | `close` |
| `workflow` | Workflows | `steps` (id, name, status, duration) | - |
| `executionGraph`| Workflows | `nodes` (id, label, type, status), `edges` | - |

---

## Interactive Serialization

Events dispatched from components to the runtime are standardized and JSON-serializable:

```json
{
  "type": "click",
  "target": "node_button_2ef4",
  "timestamp": "2026-05-30T18:00:00.000Z",
  "payload": {
    "label": "Execute Flush"
  }
}
```
