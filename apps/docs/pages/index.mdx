# GenUI Protocol

**Let AI agents answer with interfaces, not just text — without letting them write frontend code.**

An agent emits a small, declarative JSON *document*. A runtime validates it, and a renderer draws it with your own components. The model never produces HTML, CSS or JavaScript, so there is nothing to execute and nothing framework-specific to generate.

![Access request: the form submits to an agent, the agent answers with data patches, the workflow advances](/assets/demo.gif)

```json
{
  "version": "1.0.0",
  "data": { "form": { "name": "" } },
  "root": {
    "t": "card",
    "p": { "title": "Sign up" },
    "c": [
      { "t": "input", "p": { "label": "Name", "value": { "$bind": "form.name" } } },
      { "t": "text", "p": { "content": { "$tpl": "Hello {{form.name}}" } } },
      { "t": "button", "p": { "label": "Send", "onClick": { "do": "submit", "name": "signup", "from": "form" } } }
    ]
  }
}
```

## Why

- **Safe by construction.** Documents are data. Props are rendered as text, URLs are scheme-checked, size limits are enforced, and interactivity is a fixed set of declarative [actions](/protocol#11-actions).
- **Compact.** A document describes *what* to show. See the [benchmark](/benchmark).
- **Interactive.** Data binding, two-way forms and `emit`/`submit` actions let the UI talk back to the agent.
- **Live.** Sequenced stream frames and RFC 6902 patches update a UI in place, with resync when a consumer falls behind.
- **Portable.** One document, any renderer. React and Angular ship today; the [protocol](/protocol) and [conformance fixtures](https://github.com/Pranavtej/GenUI-Protocol/tree/main/conformance) are what other renderers implement.
